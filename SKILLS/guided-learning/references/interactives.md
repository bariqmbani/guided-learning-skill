# Course interactive handoff

Read when the course flow selects an interactive for explanation or application.
Construction belongs to [learning-interactives](../../learning-interactives/SKILL.md);
load that skill instead of duplicating its template, component, build, or QA rules.

Pass the outcome, concept/model and assumptions, learner language and access
constraints, session budget, and pinned topic paths: `{interactives_dir}`,
`{css_file}`, and `{build_script}`. Choose a dated output filename within that
topic. Preserve its existing assets and customizations. A supported background
helper may build while the tutor continues useful teaching; otherwise build
directly or use a worked example within the budget.

Announce the browser-openable artifact only after construction and review are
complete. Give a specific first action and let the learner explore before any
check that depends on the page. Do not delay an independent learner response for
an unfinished background build. Link HTML from the journal and open it in a
browser; Obsidian note rendering does not run its scripts.

The tutor retains assessment and records. The page does not persist answers or
update progress: record only observed learner work, the help used, and remaining
gaps. A correct selection or viewed animation is not evidence of lasting
understanding. Use explanation, a fresh case, and later recall as appropriate.
