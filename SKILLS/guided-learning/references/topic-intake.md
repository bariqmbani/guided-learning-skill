# Starting a Topic

Use this only when starting a selected track with no concept checklist. Resolve and pin the track first. For an existing course, read its plan and recent protocol, resume progress, and ask only about an explicit change or a gap relevant to the next lesson. Never rerun intake as a reason to regenerate a course.

## Ask only what is missing

Use information already provided in the request, configured profile, or selected course. Ask these in small groups rather than one long form. "I don't know yet" and "just exploring" are valid answers.

1. **Useful outcome:** "What would you like to be able to do with [topic]? Is there a project, question, or deadline we should aim for?" Convert the answer into a concrete demonstration: explain a decision, solve a kind of problem, build something, hold a conversation, or evaluate a source. For curiosity, propose a small exploratory outcome and keep it provisional. Infer domain mode from the purpose; ask only if the choice would change the lesson.
2. **Starting point:** "What have you already tried or learned about this? What can you do comfortably, and where do you get stuck? Starting from zero is fine." Treat this as provisional context. In the first lesson, use one short explanation, prediction, or task involving a prerequisite to calibrate support. Make "not sure" welcome, give feedback, and start teaching; do not impose a separate graded entrance test. Do not equate a job title, confidence, or a self-rating with mastery.
3. **Feasible practice:** "Roughly how often could you return for a session or a short review? No fixed schedule is fine." Ask about tools or materials only when the chosen activity requires them. Reuse the vault's session budget. An optional deadline sets priorities, not a guaranteed completion date. Avoid requiring a calendar or a weekly-hours commitment.

If the learner asks to start immediately, use a provisional exploratory goal and check prerequisites within teaching. Missing optional answers must not block the first useful lesson. Ask about the teaching language if not explicitly known. Do not repeat global onboarding or transfer a different topic's background, goal, or progress.

## Store decisions in the selected topic

During bootstrap, include a short **Learning plan** section in `{roadmap}`. Use plain prose or bullets for the outcome, initial demonstration of success, starting knowledge (self-report versus observed evidence), practice opportunities, optional deadline/materials, and domain mode. Unknowns stay unknown. No new global profile or registry fields are needed. Update the plan when the learner changes the goal; preserve all checklist entries and recall history.

Keep approved topic-specific lesson preferences in a separate **Teaching
preferences** section of the same roadmap. Read these alongside the vault profile;
follow [personalization.md](personalization.md) before saving new ongoing rules
inferred from feedback. An intake answer about a goal is not permission to infer
unrelated presentation preferences or change another topic.

The plan must affect teaching:

- An implementation goal gets relevant implementation practice; an explanatory goal gets explanations and transfer questions; a conversation goal gets conversational tasks.
- A beginner gets prerequisite support and worked examples. Successful independent attempts allow scaffolding to fade; difficulty or misconceptions trigger targeted support.
- A tight budget reduces the amount covered per session. A deadline prioritizes essential prerequisites and useful outcomes without promising mastery.
- Available practice opportunities determine how much new material and review to offer. Recall is checked when the learner returns; no notifications or automatic scheduling are assumed.
- A source or tool request changes the materials and activity only in this topic. Follow actual access constraints and provide a workable alternative.

The first lesson should produce one useful attempt and feedback, not just files. Avoid bundling several intake probes with the normal prerequisite checks; reuse observed answers. Revisit the success demonstration after later practice and, when possible, on a new example after a delay. A confident answer immediately after an explanation is provisional evidence, not permanent mastery.
