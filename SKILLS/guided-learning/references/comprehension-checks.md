# Comprehension Checks

Read when selecting a Phase 2 check. Choose **one** eligible format for the
current pass and domain; do not repeat the previous session's `check_format`.
Use only the selected topic's logs to find the previous format, and record the
chosen ID unchanged. Shared rows are available in every domain unless restricted.
Adapt wording to the actual concept, language, and learner while retaining the task.
If an interactive was built, let the learner explore before asking the question.
Wait for the response; re-explain gaps before advancing.

## Pass 1 — Overview

| Shared ID | Prompt |
| --- | --- |
| `predict-outcome` | If [variable] changes from X to Y, what happens and why? |
| `spot-flaw` | What's wrong with this deliberately flawed claim: “[statement]”? |
| `analogy-check` | Give your own analogy, different from the tutor's. |
| `what-breaks` | If we ignored this concept, what would go wrong? Research: in your system; professional: in production; self-study: what problems would remain unsolved? |

Choose either shared formats above or a domain variant below:

| Task | Research | Professional | Self-study |
| --- | --- | --- | --- |
| Explain to an audience | `conference-pitch`: Explain to a fellow researcher at a poster session. | `team-standup`: Explain to your team in 30 seconds. | `dinner-table`: Explain to a curious friend over dinner. |
| Explain the value | `elevator-pitch`: In 30 seconds, sell its relevance to your research. | `stakeholder-pitch`: Your VP asks why this matters for the product. | `elevator-pitch`: In one sentence, why should anyone care? |

## Pass 2 — Working Understanding

| Shared ID | Prompt and eligibility |
| --- | --- |
| `two-concept-bridge` | How does this connect to [previous concept]? What does one provide that the other doesn't? |
| `devils-advocate` | I think [opposing claim]. Convince me I'm wrong using this concept. |
| `evidence-check` | Research or self-study: What's the strongest evidence for this claim, and its biggest limitation? |
| `design-decision` | Research or professional: Where does this change your system design, and how? |
| `predict-failure` | Under what conditions would this fail? Research: give a concrete domain example; professional: consider a real deployment. |

| Task | Research | Professional | Self-study |
| --- | --- | --- | --- |
| Explain the mechanism | `advisor-pitch`: Explain the mechanism to your advisor. | `manager-briefing`: Write a one-paragraph briefing for your manager. | `teach-a-friend`: Explain the mechanism to someone smart but unfamiliar. |

Additional domain-specific formats:

- **Professional — `cost-benefit`:** What's the cost of implementing this versus not implementing it?
- **Self-study — `build-something`:** In a project using this, what would you implement first?
- **Self-study — `edge-case`:** What's the most extreme scenario where this still applies?

## Pass 3 — Fluency

| Shared ID | Prompt |
| --- | --- |
| `counter-argument` | Name a paper or concept that could argue against this claim. |
| `teach-it` | Explain to a newcomer. Research: a student who has not read the paper and needs to implement it; professional: a team member starting Monday; self-study: a motivated beginner seeking understanding rather than memorization. |

| Task | Research | Professional | Self-study |
| --- | --- | --- | --- |
| Write for an audience | `related-work`: Write one Related Work sentence about this. | `decision-memo`: Write the recommendation paragraph for a decision document. | `blog-post-opener`: Write a blog's opening paragraph explaining this. |
| Defend the concept | `reviewer-sim`: Reviewer 2 calls your use superficial. Defend it. | `pushback-sim`: A skeptical colleague calls this over-engineered. Defend it. | `skeptic-response`: Someone on Twitter calls it overrated. Draft a reply. |
| Connect to your work | `hypothesis-link`: Which hypothesis does this support, and how would you cite it as evidence? | `project-link`: Which current project benefits most, and how? | `portfolio-link`: How would you demonstrate understanding in a portfolio project? |
| State a caveat | `write-limitation`: Write a two-sentence limitation paragraph for your system. | `write-risk`: Write a two-sentence risk assessment for not applying it. | `write-caveat`: Write the two-sentence “here's the catch” paragraph. |
