    04 · Explain your decision

    Which observation changed your explanation of the bug? Name one hypothesis it weakened and one it supported. What did testing the original successful case protect against?

    One reasoned path

    Compare both profiles and the renderer. The renderer reads display_name, but the new profile supplies full_name. Support both schemas, then test the legacy, new, and missing-name cases. This explains the mismatch without assuming why the data producer changed.

    Transfer the approach

    A saved file opens on one machine but not another. What small comparison could separate a file-content problem from an environment problem? State what result you would expect under each explanation.

    Model limits. This is a scripted local debugging exercise, not a live diagnosis. Fixtures have nonempty names or missing/null fields; blank strings, localization, and network failures are outside the model. A compatibility fallback addresses the displayed symptom for these fixtures, but does not establish why the upstream schema changed.
